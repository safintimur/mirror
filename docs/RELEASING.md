# Releasing Mirror

Mirror currently ships as an experimental, ad-hoc signed macOS app. Notarization and a bundled Python runtime are not part of the current release setup.

## Validate

From the repository root, on macOS:

```sh
python3 tests/test_parity.py
./app/build.sh
codesign --verify --deep app/build/Mirror.app
git diff --check
```

Check all scenarios in the parity summary: the script's exit code only treats core scenario failures as fatal. The sandbox does not exercise real desktop sidebar refreshes; check those separately when the corresponding code changes.

Check for secrets with [Gitleaks](https://github.com/gitleaks/gitleaks):

```sh
gitleaks git . --log-opts=--all --redact
```

Also review personal paths, conversation IDs, author/committer email addresses, screenshots and Git commit messages. A secret scanner does not cover all private information.

## Source publication

The local `main` branch retains development history. `public-ready` is a separate parentless snapshot intended for the initial public repository; it uses a GitHub noreply email. Inspect its contents and metadata before pushing. Do not push all local branches or tags from the development repository.

Publishing the repository or a release requires the owner's approval. The first publication should push only the reviewed snapshot as the public repository's `main`. Develop subsequent public changes on top of that history rather than merging the private development history into it.

## Binary release

Build from the exact public revision you intend to tag. `app/build.sh` sets the version and derives the build number from that checkout's commit count.

```sh
./app/make_dmg.sh
hdiutil verify app/build/Mirror-0.2.0.dmg
shasum -a 256 app/build/Mirror-0.2.0.dmg
```

Use the version generated by the build script if it differs from this example. Verify the app's signature and bundled `LICENSE` inside the mounted image, then eject it. Confirm the installer layout and launch on a separate Mac before claiming broader compatibility.

Attach the DMG and its SHA-256 checksum to the matching GitHub pre-release. Release notes must disclose the Python requirement, unsigned-by-Developer-ID installation flow, supported provider versions and storage-format compatibility limits. Source snapshots and DMG files must never include conversation data or pairing state.

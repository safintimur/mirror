# Устройство Mirror

Техническое описание движка и интерфейса. Пользовательская инструкция — [README](../README.md).

- Codex → Claude: инкрементально дописывает элементы rollout в `~/.claude/projects/<cwd>/<uuid5(thread)>.jsonl`; записи помечены `codexItem`.
- Claude → Codex: завершённые ходы Claude дописываются в rollout нативными `CommandExecution` / `FileChange` / `McpToolCall` под writer-lock Codex.
- Занятая сторона не трогается: тред загружен в Codex (lock держится до выхода из приложения) или сессия открыта в Claude (`--resume`). Работа ждёт следующего `sync`.
- Песочница: `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `MIRROR_STATE_DIR`. Проверка разбора — `codex app-server` на песочнице, `thread/turns/list` (удалить `thread_history_1.sqlite`, если rollout заменён).
- Условие: штатный импорт Codex выключен (`external-agent-import-sync-enabled = false`), иначе он плодит дубли.

## Приложение Mirror (`app/`)
Нативное menu bar приложение (SwiftUI, macOS 26) поверх движка: статус тредов, фоновая синхронизация, «Освободить Codex/Claude» (предупреждение → закрыть → синхронизировать → открыть снова). Дизайн — `app/DESIGN.md`.
- Сборка: `app/build.sh` → `app/build/Mirror.app` (движок кладётся в Resources, подпись ad-hoc). Версия задаётся в `build.sh`, номер сборки — число коммитов.
- Иконка: `app/Resources/Mirror.icon` (Icon Composer, светлый и тёмный варианты, Liquid Glass) компилируется `actool` при сборке.
- DMG: `app/make_dmg.sh` → `app/build/Mirror-<версия>.dmg` (окно «перетащите в Applications»; фон — `app/Resources/dmg/background.svg` → `background.tiff` 1x+2x). Finder раскладывает окно, поэтому образ ненадолго монтируется.
- Текущие сборки используют подпись ad-hoc, без нотаризации. На другом Mac может понадобиться разрешить запуск в настройках безопасности; движок пока требует доступный `/usr/bin/python3`.
- Первый запуск — на паузе: первая синхронизация создаёт много тредов и включается кнопкой.
- Отладка: `MIRROR_SHOW=1` (окно при запуске), `MIRROR_TAB=all|settings|release-claude`, `MIRROR_ICON_PREVIEW=out.png`; пути движка — через `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `MIRROR_STATE_DIR`.

## Как треды появляются в интерфейсах
- **Codex** показывает только треды из своей базы `state_5.sqlite` и новые файлы в `sessions/` не сканирует. Созданный rollout регистрируется штатным вызовом `thread/name/set` через короткоживущий `codex app-server` (тред получает имя сессии Claude).
- **Claude desktop** держит список сессий в `claude-code-sessions/<org>/<account>/local_<id>.json` и загружает его при старте. Движок пишет запись в формате импорта терминальных сессий, а работающее приложение подхватывает сессию по официальной ссылке `claude://resume?session=<id>` (`open -g`). Импорт выводит Claude на передний план, поэтому автосинхронизация делает его только после минуты простоя пользователя; ручная синхронизация (`sync --manual`, кнопка в Mirror) — сразу.
- Папка проекта Claude для длинных путей: первые 200 символов + `-` + base36-хеш пути (как в Claude Code), иначе Claude не найдёт зеркало.

## Паритет изменений тредов
| Изменение | Claude → Codex | Codex → Claude |
|---|---|---|
| Переименование (только ручное) | `thread/name/set` | запись в реестр Claude |
| Архивация / разархивация | `thread/archive` / `thread/unarchive` | `isArchived` + `archived-sessions.idx` |
| Удаление | архив в Codex | архив в Claude |

- В Codex изменения идут штатными вызовами `app-server` сразу; его боковая панель обновится после перезапуска (движок взводит флаг сверки каталога, только пока Codex закрыт).
- В Claude внешнего API нет: изменения копятся в очереди (`pending_claude`) и записываются в реестр только пока Claude закрыт — во время «Перезапустить и синхронизировать» в Mirror. Гонки с работающим приложением нет.
- Переносятся только изменения после связывания; свои записи движок запоминает и обратно не отправляет. Изменение, отменённое до применения, из очереди убирается. Удаление в Codex засчитывается, только если база прочиталась и пропало не больше трёх тредов за проход.

## Перезапуск (паритет Codex и Claude)
- Codex держит открытые треды до выхода, Claude держит сессию, пока жив её процесс (с Remote Control — бессрочно). Оба приложения освобождаются одинаково: полный перезапуск.
- Главная кнопка Mirror: «Перезапустить» только если ходы ждут закрытия приложения (`blocked`), иначе «Синхронизировать». Косметика (архив, названия, список) не требует перезапуска: строка статуса подсказывает «изменения при следующем запуске».
- Перезапуск: общий лист предупреждения (прервутся ходы, закроются сессии, может пропасть черновик Claude) → закрыть → синхронизировать → открыть, по одному приложению, свободное первым. «Дождаться» ждёт не дольше 15 минут; занятое дольше приложение не трогается, остальное синхронизируется.
- Вызовы движка из приложения ограничены 180 с; скрытая панель ничего не рендерит (0% CPU в покое).
- `status` сообщает по каждому приложению `blocked` (ходы, ждущие его перезапуска) и `restart_needed`.
- Настройка «Перезапускать при простое» (выкл. по умолчанию, работает с автосинхронизацией): 5 минут без ввода и нет идущих ходов.

## Ограничения
- Форки сессий Claude «(fork)» и продолжение под новым id заводятся как отдельные треды.
